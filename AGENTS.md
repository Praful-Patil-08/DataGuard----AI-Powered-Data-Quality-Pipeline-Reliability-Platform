# DataGuard Engineering Rules

## Product

DataGuard is an AI-powered data reliability platform.

## Architecture

Frontend:
Next.js + TypeScript + Tailwind

Backend:
Python + FastAPI

Database:
PostgreSQL

AI:
OpenAI API / OpenAI Agents SDK

## Rules

1. Do not over-engineer.
2. Implement MVP features before abstractions.
3. Never let the LLM perform deterministic validation.
4. Never allow AI to modify production data automatically.
5. All AI remediation requires human approval.
6. Keep business logic testable without OpenAI.
7. Use typed schemas for API requests/responses.
8. Add tests for every new feature.
9. Update documentation when architecture changes.
10. Do not introduce dependencies without justification.
11. Keep frontend and backend independently testable.
12. Never expose OPENAI_API_KEY to the browser.
13. Never execute arbitrary SQL generated by an LLM without validation.
14. Never claim an action was performed unless it actually happened.
15. Keep AI suggestions separate from deterministic scan results.

## Development Process

For every task:

1. Inspect existing code.
2. Explain intended changes.
3. Implement.
4. Run tests.
5. Fix failures.
6. Update documentation.
7. Show changed files.
8. Do not modify unrelated code.
